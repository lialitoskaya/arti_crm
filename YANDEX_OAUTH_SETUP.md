# Быстрый вход через Яндекс — настройка

Интеграция добавляет кнопку **«Войти через Яндекс»** на существующий экран входа CRM.

Важно:

- это OAuth-вход, а не двухфакторная аутентификация;
- новые CRM-пользователи автоматически не создаются;
- каждый разрешённый аккаунт Яндекса явно связывается с уже существующим активным пользователем CRM;
- если у пользователя CRM включён локальный TOTP, после Яндекса всё равно потребуется одноразовый код;
- OAuth access token используется только для чтения профиля и не сохраняется в БД.

## 1. Создать приложение в Яндекс OAuth

1. Войдите в Яндекс под корпоративным аккаунтом, доступ к которому не будет потерян.
2. Откройте страницу создания приложения для авторизации:
   `https://oauth.yandex.ru/client/new/id/`
3. Выберите приложение для входа пользователей / веб-сервис.
4. Укажите название и контактную почту.
5. Добавьте Redirect URI:

   `https://perfectservice-crm.ffox.site/api/auth/yandex/callback`

   Если CRM работает на другом домене, замените домен. Схема, домен, порт и путь должны совпадать с фактическим адресом callback.
6. Разрешите базовый доступ к данным Яндекс ID, необходимый для получения идентификатора и логина. Доступ к email требуется только при использовании привязки `email:`.
7. Сохраните выданные `ClientID` и `Client secret`.

Создавайте именно приложение **для авторизации пользователей**, а не приложение только для API-доступа.

## 2. Добавить переменные окружения на сервере

```env
YANDEX_OAUTH_ENABLED=1
YANDEX_OAUTH_CLIENT_ID=ВСТАВЬТЕ_CLIENT_ID
YANDEX_OAUTH_CLIENT_SECRET=ВСТАВЬТЕ_CLIENT_SECRET
YANDEX_OAUTH_REDIRECT_URI=https://perfectservice-crm.ffox.site/api/auth/yandex/callback
YANDEX_OAUTH_USER_MAP={"login:YANDEX_LOGIN":"CRM_USERNAME"}
```

Пример для нескольких сотрудников:

```env
YANDEX_OAUTH_USER_MAP={"login:owner_yandex":"admin","login:manager_yandex":"manager1","id:123456789":"viewer1"}
```

Где:

- `owner_yandex` — логин аккаунта Яндекса;
- `admin` — существующий username в CRM;
- `id:123456789` — стабильный ID аккаунта Яндекса; после первого теста его можно использовать вместо логина;
- `email:user@yandex.ru` допустим только при выданном приложению доступе к email.

В панели хостинга JSON обычно вводится без внешних одинарных кавычек. Не добавляйте пробелы и переносы внутрь значения, если панель их обрабатывает некорректно.

## 3. Установить зависимости

Интеграция не добавляет новых библиотек: используется уже установленный `httpx`.

Из корня сайта с активированным виртуальным окружением:

```bash
python -m pip install -r requirements.txt
python -m pip check
```

## 4. Заменить файлы и перезапустить CRM

Скопируйте файлы из архива с сохранением структуры каталогов. Затем перезапустите приложение через панель хостинга или используемую службу запуска.

Проверка конфигурации:

```text
GET /api/auth/yandex/status
```

Ожидаемый ответ:

```json
{"enabled": true}
```

Если возвращается `false`, проверьте наличие всех четырёх обязательных параметров и корректность JSON в `YANDEX_OAUTH_USER_MAP`.

## 5. Проверить вход

1. Откройте CRM в режиме инкогнито.
2. Убедитесь, что появилась кнопка «Войти через Яндекс».
3. Нажмите её и выберите разрешённый аккаунт Яндекса.
4. После возврата в CRM должна появиться обычная авторизованная сессия.
5. Для CRM-пользователя с включённым TOTP появится дополнительное поле одноразового кода.

## Безопасность и эксплуатация

- `YANDEX_OAUTH_CLIENT_SECRET` хранится только в переменных окружения и не должен попадать в Git или архивы.
- Вход использует Authorization Code flow, `state` и PKCE S256.
- Временный OAuth-flow хранится только в подписанной HttpOnly cookie сроком 10 минут.
- Аккаунты без явной записи в `YANDEX_OAUTH_USER_MAP` получают отказ.
- Не используйте общий аккаунт Яндекса для нескольких сотрудников.
- При увольнении сотрудника отключите его CRM-пользователя и удалите соответствующую запись из `YANDEX_OAUTH_USER_MAP`.
- После смены `Client secret` обновите значение на сервере и перезапустите все workers.
