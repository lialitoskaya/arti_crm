# Найденные баги бизнес-логики и функциональные дефекты (не исправляются в рамках UI/UX-задачи)

Фиксируются по ходу аудита. Каждая запись: где, как воспроизвести, ожидаемое поведение, доказательство.
Исправления здесь не делаются — решение о приоритете за владельцем.

## 1. Раздел «Отзывы» падает при непустом списке: `reviewModelName is not defined`

- **Где:** `app/static/app.js:4929`, `4951`, `4958` — вызовы `reviewModelName(review)` в `renderReviewsList` и `openReview`.
  Функция нигде не определена (`grep -n reviewModelName app/static/app.js` даёт только три вызова; в истории git
  строки `function reviewModelName` нет ни в одном коммите, вызов присутствует с начального коммита `4458ca1`).
- **Воспроизведение:** любой непустой ответ `GET /api/reviews` → `renderReviewsList()` бросает `ReferenceError`,
  `loadReviews` → `notify('Ошибка загрузки отзывов', 'reviewModelName is not defined')` (блокирующий `alert`),
  список остаётся пустым. На локальном стенде с 14 синтетическими отзывами воспроизводится при каждом открытии
  раздела и при каждом `refreshVisibleData` (раз в 60 с), пока раздел открыт — см. `audit/screenshots/before/before-reviews-*.png`
  и журнал `before-report.json` (поле `dialogs`).
- **Почему не замечено:** в `.env.example` `OZON_REVIEWS_BACKGROUND_SYNC=false`, поэтому на хостинге таблица `reviews`,
  вероятно, пуста и рендер списка не выполняется. Любая ручная синхронизация («Обновить» в разделе) сломает раздел.
- **Ожидаемое поведение:** название модели/товара в строке и заголовке отзыва (`review.product_name`, fallback `sku`),
  по аналогии с `questionProductName` (`app.js:5168`).
- **Тесты:** ни один тест в `tests/` не покрывает `renderReviewsList` (grep пустой).
- **Предложение:** одна функция `reviewModelName(review)` рядом с `reviewRatingStars` + характеризационный UI-тест,
  запускающий `renderReviewsList` через node (как `tests/test_chat_read_state_ui.py`). Относится к рендерингу раздела
  «Отзывы», поэтому может войти в этап 5 после подтверждения владельца.

## 2. Роль `manager` не может выполнять изменяющие действия (RBAC)

- **Где:** `app/auth_dependencies.py:route_access_class` — любой `POST/PUT/PATCH/DELETE` под `/api/`, кроме явного
  списка self-service, классифицируется как `admin_only`; `app/main.py:455` применяет это в middleware ко всем ролям.
- **Следствие:** пользователь с ролью «Менеджер» получает 403 на создание задачи, ответ на отзыв/вопрос, отправку
  сообщения, создание статьи — при этом UI показывает эти действия всем авторизованным (класс `admin-only` скрывает
  только раздел сотрудников, тех. настройки, FBO и создание статей).
- **Проверено на стенде (2026-10-30):** вход под ролью `manager` → `POST /api/tasks/standalone` → `403 {"detail":"Нужны права администратора"}`,
  `POST /api/reviews/1/reply` → `403`, `GET /api/tasks` → `200`. Интерфейс при этом показывает менеджеру кнопки
  «Новая задача», «Ответить», «Создать задачу» и завершает их `alert` с текстом 403.
- **Статус:** требует подтверждения владельца, является ли это намеренной политикой (все сотрудники — администраторы)
  или регрессией hardening (`tests/test_route_rbac.py` фиксирует только viewer/admin, роль manager тестами не описана).
  В UI-плане предлагается скрывать/блокировать изменяющие действия по `currentUser.role` только после решения владельца.

## 3. Нижняя навигация на мобильных не даёт доступа к разделам «Ещё»

- **Где:** `app/static/styles.css:322–323` (`.mobile-more-btn { display: none }`), `1257` (`.mobile-more-sheet { display: none }`);
  ни одно media-правило их не включает; стилей для `.mobile-more-card/-item/-list` нет.
- **Следствие:** на ≤900px кнопка «Ещё» и лист с пунктами «Сотрудники», «Настройки», «Профиль», «Уведомления»,
  «Выйти» никогда не отображаются; вместо этого полоса навигации растягивается до ~15 иконок с горизонтальной
  прокруткой без подсказки (проверено на стенде при 375px: `#mobileMoreBtn` → `display: none`, `navOzonFbo`
  правый край 389px при ширине 375px).
- **Классификация:** это UI-дефект, входит в план этапа 5 (раздел «Оболочка»); зафиксирован здесь, потому что
  ограничивает доступ к функциям на телефоне.

## 4. Маршрут `#questions/<id>` и восстановление раздела после перезагрузки

- **Наблюдение на стенде:** при перезагрузке страницы с `#questions` после ошибки в разделе «Отзывы» открылся
  раздел «Отзывы» (см. `audit/screenshots/before/before-questions-*.png`, если на снимке «Отзывы Ozon»).
  Причина проверяется в `getInitialRouteView` (`app/static/app.js:7225`) — приоритет сохранённого
  `localStorage['artiCrm.activeView']` над hash. Статус: уточняется (см. `01-ui-ux-issues.md`).
