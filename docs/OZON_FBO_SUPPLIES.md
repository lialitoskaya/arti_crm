# Поставки FBO Ozon

Раздел CRM «Поставки FBO» создаёт заявки на поставку FBO в Ozon по плану: читает план по
артикулам и кластерам, подбирает количество, которое кластер реально принимает, выбирает
самый поздний таймслот, после подтверждения создаёт заявки и передаёт грузоместа. Функции
перенесены один к одному из desktop-приложения «Поставки FBO Ozon» (пакет `ozon_fbo`);
отличие в том, что память о заявках, настройки и журнал прогонов живут в базе CRM и видны
с любого компьютера.

Раздел доступен только администратору. Ключи Ozon Seller API в интерфейсе не вводятся.

---

## 1. Быстрый старт

1. Убедитесь, что в окружении сервера заданы `OZON_CLIENT_ID` и `OZON_API_KEY` (см. раздел 9).
   В шапке раздела написано, заданы ли ключи; кнопка «Проверить связь с Ozon» делает безопасный
   запрос списка кластеров.
2. Скачайте лист из Google Таблиц: **Файл → Скачать → Microsoft Excel (.xlsx)** или подготовьте
   строки «артикул; кластер; количество» для ручного ввода.
3. В блоке «Запуск» выберите режим **«Пробный прогон»**, источник плана, файл и лист (или строки),
   нажмите «Запустить пробный прогон».
4. Проверьте журнал и таблицу результатов. Если всё верно, выберите боевой режим и запустите снова.
   Расчёт повторится, затем появится диалог «План поставок». Заявки создаются только после кнопки
   «Создать заявки».

Пробный прогон ничего не создаёт в кабинете Ozon. В отчёте встречается «расчётный черновик» с
номером: это служебный объект API, который живёт 30 минут и в списке черновиков кабинета не
отображается.

## 2. Блок «Запуск»

**Режимы**

| Режим | Что делает |
|---|---|
| Пробный прогон | Считает «Факт» и слоты, заявки не создаёт |
| Боевой — создать заявки и сразу передать грузоместа | Основной режим: расчёт → план → подтверждение → заявки и грузоместа |
| Боевой — создать заявки без грузомест | Только заявки; коробы можно передать позже режимом «Дозаполнить» |
| Дозаполнить грузоместа по уже созданным заявкам | Передаёт коробы по заявкам Ozon в состоянии «заполнение данных», в том числе созданным в ЛК |

**Источник плана**

- **Таблица .xlsx.** После выбора файла CRM читает список листов и подставляет последний.
  Читаются колонки «Артикул», «Кластер» и «Заявку на поставку» (план). Строки, скрытые фильтром,
  пропускаются и перечисляются в начале журнала. Результат — копия книги с заполненной колонкой
  «факт» (нули красным) и колонкой «Заявка / примечание»; скачивается кнопкой «Скачать результат
  .xlsx» после завершения прогона. Исходный файл не меняется.
- **Ручной ввод.** Строки `артикул; кластер; количество`, по одной на кластер; разделитель «;» или
  табуляция (можно вставить три столбца из таблицы). «Название списка» нужно, чтобы CRM помнила
  созданные по этому списку заявки.

Везде вместо артикула можно указать SKU Ozon (число): CRM сама найдёт артикул и дальше работает с
ним. Вместо названия кластера можно написать `все`: строка разворачивается в строку на каждый
кластер из настройки «Какие кластеры считать «все»» (пусто — все кластеры России, их 20). Явная
строка по кластеру важнее строки «все».

**Артикулы** — необязательный фильтр через запятую.

**Галочки**

| Галочка | Что делает |
|---|---|
| Повторить по артикулам, у которых заявка уже есть | Отключает память CRM о созданных заявках по этому списку. Дневное правило «один артикул на склад — одна заявка» не отключает |
| Подтверждать каждый артикул отдельно | Вопрос перед каждой заявкой вместо одного общего плана |
| Не спрашивать подтверждение вообще | План подтверждается автоматически. Вопрос про дубли этой галочкой не отвечается |

Перед запуском боевого режима браузер показывает предупреждение. Одновременно может идти только
один прогон: это гарантирует уникальный индекс в базе, второй запуск получает ошибку 409.

## 3. Панель «Прогон»

Панель показывает текущий или последний прогон: статус, режим, список, кто запустил, время,
журнал (тот же текст, что в отчёте), таблицу результатов и ссылки на файлы.

| Статус | Смысл |
|---|---|
| В очереди / Выполняется | Рабочий поток считает или создаёт заявки |
| Ждёт ответа | Прогон задал вопрос (дубли, план, подтверждение по артикулу); появляется диалог |
| Завершён | Прогон закончился штатно |
| Остановлен | Нажата кнопка «Остановить»; созданное осталось |
| Ошибка | Прогон упал: причина в строке статуса и в журнале |
| Прерван | Рабочий процесс перестал отвечать (перезапуск сервера); снят автоматически или кнопкой |

Таблица результатов: артикул, кластер, план, факт, статус строки («принято», «исключён», «ручная
проверка») и примечание с номером заявки или причиной.

Файлы: «Отчёт прогона» (журнал текстом), «Логи запросов Ozon» (zip с сырыми запросами и ответами
без заголовков), «Скачать результат .xlsx» для прогонов из таблицы.

**Диалог решения.** Пока прогон ждёт ответа, оранжевая полоса «прогон ждёт вашего ответа» и
диалог с текстом вопроса. Кнопки зависят от вопроса: «Создать заявки» / «Отмена» для плана
поставок, «Передать грузоместа» / «Отмена» для плана грузомест, «Всё равно сделать» / «Пропустить
дубли» для дублей, «Да» / «Нет» для подтверждения по артикулу. Диалог можно закрыть (Esc) и открыть
снова кнопкой в полосе. Черновики Ozon действуют 30 минут: устаревшие пересобираются автоматически,
а ответ, не полученный за два часа, считается «нет».

**Остановить** завершает прогон после текущего артикула. **Снять зависший прогон** появляется,
когда heartbeat прогона старше трёх минут (рабочий процесс погиб): прогон помечается прерванным,
созданные заявки уже сохранены по каждому артикулу. То же делает автоматически открытие раздела.

## 4. Режим «Дозаполнить грузоместа»

1. Выберите режим — вместо источника плана появится список заявок.
2. Нажмите «Загрузить заявки из Ozon». Показываются все заявки в состоянии «заполнение данных»:
   номер, дата, слот, срок, склад и товары с раскладкой по коробам.
3. Все заявки выделены сразу; снимите лишние галочки или нажмите «Выделить все».
4. Нажмите «Запустить передачу грузомест». Появится «План грузомест»; коробы уйдут в Ozon только
   после кнопки «Передать грузоместа».

Перед отправкой заявка и состав перечитываются и проверяются: поставка ждёт данных, по каждому
артикулу сумма по коробам равна составу, короб не пуст и не больше вместимости, каждый короб —
один артикул. Поставка, отменённая Ozon внутри заявки, пропускается с пометкой, остальные
заполняются. После передачи заявка уходит в «готова к отгрузке» и в списке больше не появляется.

## 5. Как CRM считает

**Количество по кластеру.** План P, кластер реально принимает A.

| Условие | Результат |
|---|---|
| A ≥ P | В поставку идёт P, даже если P не кратно пяти |
| A < P и A ≥ 10 | A, округлённое вниз до кратного пяти: 38 → 35, 23 → 20, 14 → 10 |
| A < P и A < 10 | Кластер исключается, «Факт» 0 |

Ozon не сообщает A: сначала один общий черновик по плану на все кластеры артикула. Если Ozon
принял всё и дал слот — это итог. Иначе проблемные кластеры подбираются отдельными черновиками
(кандидаты: план, затем кратные пяти вниз до минимума, половинным делением, урезание Ozon — как
подсказка), затем собирается итоговый черновик. Если в итоговом черновике Ozon отказал кластеру,
состав повторяется один раз, затем кластер исключается (пометка «исключён в итоговом черновике»)
и черновик пересобирается, не больше четырёх итоговых черновиков.

**Слот.** Один таймслот на поставку, на точке сдачи: самая поздняя дата не раньше сегодня + N дней,
в ней самое позднее время. Слоты запрашиваются окнами по 28 дней, пока Ozon их отдаёт.

**Грузоместа.** Коробы по вместимости (по умолчанию 50, для отдельных артикулов своя), остаток в
последнем, каждый короб моно-SKU, раскладка по каждому кластеру отдельно.

**Лимиты Ozon.** Не больше одного запроса в секунду и двух черновиков в минуту; CRM выдерживает их
сама, отказ «кластер недоступен» повторяется один раз через паузу из настроек. Лист из 13 артикулов
занимает около 7 минут, с подбором по кластерам — до 30–40.

## 6. Защита от ошибок

**Предохранители перед каждой заявкой.** Заявка не создаётся, артикул помечается для ручной
проверки, если факт больше плана; факт не равен плану и не кратен пяти; факт не ноль и меньше
десяти (кроме плана меньше десяти, принятого целиком); количество в черновике не совпадает с
фактом; слот раньше чем через N дней; по артикулу уже создана заявка; такая же поставка сегодня уже
есть у Ozon.

**Дубли.** Правило: по одному артикулу на один склад не больше одной заявки в день. Проверяется по
заявкам самого Ozon за сегодня (по Москве), включая созданные в ЛК. Поставка CRM «на кластер»
блокируется любой сегодняшней заявкой в этот кластер, потому что склад выбирает Ozon. Карта
склад → кластер берётся из справочника кластеров и доучивается бесплатными черновиками прямой
поставки; выученные склады хранятся в таблице `ozon_fbo_warehouse_map`.

**«Всё равно сделать».** Если дубли нашлись или по этому списку заявка уже создавалась (память
CRM), прогон один раз, до расчёта, задаёт вопрос со списком строк. «Всё равно сделать» действует на
весь прогон: строки идут в поставку с пометкой «дубль по решению пользователя», в плане помечены
«⚠ ДУБЛЬ». Галочка «без подтверждения» этот вопрос не отвечает: без ответа дубли пропускаются.

**Память созданных заявок.** Таблица `ozon_fbo_article_state` хранит, что создано по каждому списку
и артикулу. Перед пропуском записанная заявка сверяется с Ozon: отменённая в ЛК не считается.
Снять память можно галочкой «Повторить…» или ответом «всё равно сделать».

## 7. Настройки

Хранятся в таблице `ozon_fbo_settings`, действуют на следующий прогон.

| Параметр | По умолчанию |
|---|---|
| Вместимость грузоместа по умолчанию | 50 |
| Вместимость для отдельных артикулов | AT-L-AM-S, AT-L-AM-M, AT-L-AM-P по 5 |
| Тип грузоместа | BOX |
| Точка сдачи | КИЕВСКИЙ_2 |
| Слот не раньше чем через N дней | 7 |
| Окон по 28 дней вперёд | 6 |
| Минимум штук в кластер | 10 |
| Кратность количества | 5 |
| Пауза перед повтором при «кластер недоступен» | 30 сек |
| Какие кластеры считать «все» | пусто (все кластеры России) |

Неверное значение не сохраняется: ошибка показывается под формой, остальные поля не меняются.

## 8. Устройство

```text
app/ozon_fbo_router.py                 маршруты /api/ozon-fbo/* (admin-only)
  -> app/services/ozon_fbo/runner.py   поток прогона, вопросы/ответы и heartbeat через БД
    -> app/services/ozon_fbo/*.py      правила, черновики, дубли, заявки, грузоместа, конвейер
      -> app/integrations/ozon_fbo/client.py   HTTP к Ozon Seller API (httpx), лимиты, дампы
      -> app/ozon_fbo_repository.py           таблицы ozon_fbo_* в SQLite
```

Таблицы: `ozon_fbo_settings`, `ozon_fbo_runs` (с уникальным индексом «один активный прогон»),
`ozon_fbo_run_log`, `ozon_fbo_run_rows`, `ozon_fbo_article_state`, `ozon_fbo_order_state`,
`ozon_fbo_warehouse_map`, `ozon_fbo_learned_clusters`. Все создаются через
`CREATE TABLE IF NOT EXISTS` в `init_db()`; откат к старому коду оставляет их неиспользуемыми.

Прогон выполняет поток внутри процесса приложения; всё его состояние в БД, поэтому опрос, ответ и
остановка работают из любого процесса хостинга. Сырые запросы и ответы Ozon (без заголовков)
пишутся в `OZON_FBO_LOG_DIR/run_<id>/` (по умолчанию `logs/ozon_fbo/`); каталог не коммитится.

API:

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/ozon-fbo/status` | ключи, активный прогон, настройки; снимает прогоны без heartbeat |
| GET / PUT | `/api/ozon-fbo/settings` | настройки |
| POST | `/api/ozon-fbo/check-connection` | безопасный запрос списка кластеров |
| POST | `/api/ozon-fbo/workbook-sheets` | листы загруженной книги .xlsx |
| GET | `/api/ozon-fbo/awaiting-cargo-orders` | заявки Ozon, ожидающие грузомест |
| POST / GET | `/api/ozon-fbo/runs` | создать прогон (multipart) / история |
| GET | `/api/ozon-fbo/runs/{id}?after=seq` | прогон, хвост журнала, строки результатов |
| POST | `/api/ozon-fbo/runs/{id}/answer` | ответ `yes`/`no` на вопрос прогона |
| POST | `/api/ozon-fbo/runs/{id}/stop` | остановить после текущего артикула |
| POST | `/api/ozon-fbo/runs/{id}/release` | пометить прогон без heartbeat прерванным |
| GET | `/api/ozon-fbo/runs/{id}/result.xlsx` | копия таблицы с результатом |
| GET | `/api/ozon-fbo/runs/{id}/report.txt` | журнал текстом |
| GET | `/api/ozon-fbo/runs/{id}/api-log.zip` | дампы запросов Ozon |

## 9. Переменные окружения

```env
OZON_CLIENT_ID=
OZON_API_KEY=
OZON_FBO_CLIENT_ID=
OZON_FBO_API_KEY=
OZON_FBO_LOG_DIR=logs/ozon_fbo
```

Раздел использует общие ключи Ozon; `OZON_FBO_*` задаются, если для поставок нужен отдельный ключ.
У ключа должны быть права на поставки FBO и на товары. Значения ключей не хранятся в БД, не
отдаются API и не попадают в журналы и дампы.

---

## 10. Что не автоматизировано

Этикетки на грузоместа, данные автомобиля для пропуска, смена слота у созданной заявки, работа
напрямую с Google Таблицей. Telegram-бот поставок остаётся отдельной программой и с разделом CRM
не связан: одновременный запуск из бота и из CRM защищён только проверкой дублей по заявкам Ozon.
