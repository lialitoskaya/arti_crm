# Права сотрудников по разделам

Администратор открывает **Сотрудники**, выбирает сотрудника, нажимает **Редактировать** и сохраняет права для каждого раздела. Те же поля есть при создании сотрудника.

| Уровень | Что доступно |
| --- | --- |
| Нет доступа | Раздел скрыт из меню. Сервер отклоняет запросы к его данным. |
| Просмотр | Чтение, поиск и фильтрация. В чатах сотрудник может менять собственные отметки о прочтении и закреплении. |
| Работа с данными | Просмотр и рабочие действия раздела, например отправка ответа, изменение задачи или редактирование статьи. |

Права назначаются для чатов, задач, отзывов, вопросов, базы знаний, аналитики, планирования поставок, поставок FBO и технических настроек. У администратора полный доступ. Управление сотрудниками, привязками Яндекса, системной синхронизацией, настройками подключения FBO и его журналом API доступно только администратору. Защита от отключения последнего администратора действует и при одновременном редактировании.

Новый сотрудник получает доступ к профилю. Администратор выбирает остальные разделы. Сотрудники, созданные до обновления, сохраняют просмотр чатов, задач, отзывов, вопросов, базы знаний и аналитики. Вход по паролю и через привязанную учётную запись Яндекса использует права одного сотрудника CRM. Изменение прав действует со следующего запроса, в том числе в уже открытом сеансе.

Задача, связанная с чатом, требует доступа к обоим разделам. Сотрудник с доступом только к задачам видит самостоятельные задачи. Для детализации аналитики до чатов нужен просмотр чатов, а для создания чата из отзыва нужны права работы с отзывами и чатами. Уведомления учитывают текущие права получателя. При просмотре планирования поставок видны данные, ранее загруженные в этом браузере.

## Установка на действующий хостинг

1. Сохраните резервную копию файлов приложения и согласованную резервную копию действующей базы SQLite средствами хостинга или SQLite Backup. Храните копии вне публичной папки сайта.
2. На время замены файлов закройте внешний доступ к CRM. Распакуйте содержимое архива обновления в корень запущенного приложения с сохранением каталога `app/`. В текущей конфигурации домен `perfectservice-crm.ffox.site` обслуживает процесс из `/var/www/vh20540/data/www/vh20541.ffox.site/`.
3. В консоли хостинга выполните `pm2 restart vh20541.ffox.site`. При запуске CRM сама добавляет поле прав к таблице сотрудников. Существующие назначения сохраняются при повторном запуске.
4. Обновите страницу через Ctrl+F5. Откройте форму сотрудника под администратором, назначьте доступ тестовой учётной записи и сохраните. В отдельном браузерном профиле проверьте доступный раздел, отсутствие закрытого раздела и блокировку редактирования при просмотре. После проверки откройте сайт сотрудникам.

Если придётся откатывать приложение, держите внешний доступ закрытым. Старая версия использует прежние правила и может показать сотруднику разделы, закрытые индивидуальными правами. Перед восстановлением базы учтите новые записи, появившиеся после резервного копирования.
